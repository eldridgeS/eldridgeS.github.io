During my Summer 2026 internship at Astera Labs, I owned the end-to-end UVM verification for the Debug Memory block of the Rx DSP. This critical module captures the internal state of the DSP across 17 different signal groups, allowing post-silicon validation engineers to observe the inner workings of the chip.
The Python-based Field-Decoding Viewer parsing raw hex dumps.
Comprehensive Test Suite
I developed a fully integrated ~47-item UVM test plan spanning data path integrity, field packing, timing configurations, control loops, and stress testing. This suite was seamlessly integrated into the team's existing Universal Verification Methodology (UVM) infrastructure, reusing agents and scoreboards that the team already trusted.

Test Plan Breakdown

  • Sanity: Force-based smoke tests, fault injection, and glitch immunity runs.
  • Data: Sweeping across all signal groups verifying data path and bit-level field packing correctness.
  • Timing: Verifying sample-period decimation, clock gapping, and synchronization alignment.
  • Control & Stress: Reset stress, BIST mode switching, full config sweeps, and randomized X-leak stress testing.
  • Integration: Wired the tests directly into the team's CI pipeline for push, nightly, and weekly regressions.
The Field-Decoding Viewer (dbgmem_viewer.py)
One of the major challenges with the debug memory was interpretability. The output is a raw stream of hex data containing heavily packed and interleaved DSP state variables. To solve this, I developed dbgmem_viewer.py, a 2,500+ line Python interactive dashboard.

Viewer Features

  • Turns raw hex dumps into context-aware, decoded per-group fields.
  • Provides a visual Pass/Fail test suite matrix.
  • Generates a reconstructed waveform viewer and bitfield map directly from the logs.
  • Dramatically reduced debug time by turning opaque hexadecimal arrays into human-readable signal timelines.
